# Development and verification

Use [README](../README.md) for initial setup, [architecture](architecture.md) for implementation boundaries, and [milestones](milestones.md) for authorized product direction and outstanding acceptance work.

## Tooling

Use the Bun version declared in `package.json` and commit dependency changes with `bun.lock`. Vite and Vitest currently use their standard Node-based CLIs through Bun scripts, so retain the Node requirement documented in README.

Use `bun install --frozen-lockfile` to verify an unchanged lockfile. Use `bun add` or `bun add -d` when dependencies change. Script definitions in `package.json` and configuration in `vite.config.ts` are the sources of truth for available commands and test discovery.

Run tests through `bun run test` so they use Vitest and the configured DOM environments. The command `bun test` invokes Bun's separate test runner.

Vite development and preview require the ignored mkcert pair described in [README](../README.md). Tests and production builds deliberately skip loading it, allowing CI and fresh checkouts to validate without private keys. When changing TLS configuration, verify an HTTPS response with the certificate’s hostname and confirm `.cert/` remains ignored.

Wrangler is a development dependency for Cloudflare Workers Static Assets. `bun run deploy:check` rebuilds and validates the deployment configuration locally without uploading or requiring login. `bun run preview:worker` rebuilds and serves the result using Wrangler on localhost; unlike Vite development/preview, this command does not load mkcert files. Wrangler state (`.wrangler/`) and local environment values (`.dev.vars*`, `.env*`) are ignored. Use the [README deployment instructions](../README.md#deploy-to-cloudflare-workers) for authentication and Workers Builds settings.

## Choosing verification

For implementation changes, run `bun run test` and `bun run build`. Add focused regression coverage for new behavior or fixed bugs where useful. Report failures or checks that could not run.

- `tests/obs.test.ts` uses a real local WebSocket server simulating OBS v5, including authentication. It covers top-to-bottom scene ordering at connection time and after `SceneListChanged`, alongside request ordering, events, session state, and failure behavior.
- `tests/reachability.test.ts` covers OBS Hello validation, unauthenticated probing, network failures, timeout, and cancellation using a controlled WebSocket double.
- `tests/connection-status.test.tsx` covers badge rechecks, unmount cleanup, and discarded results after URL edits.
- `tests/connections.test.tsx` uses Testing Library with jsdom for profile management, password forms, and independent per-profile reachability badges. Its dialog methods are shimmed; it does not prove native dialog focus or browser layout behavior.
- `tests/studio.test.tsx` covers dropdown selection versus explicit transition triggering, scene selection, independent Preview/Program indicators, busy-state guards, and the combined preview toggle with independent-menu synchronization and persisted settings. It also covers scene context menus, touch long-press opening without Preview selection, hidden-scene filtering/indicators/restoration, and the appbar visibility checkbox (in `tests/navigation.test.tsx`). Protocol tests cover hidden-status persistence across reconnects, collection isolation, single-scene generation with Preview restoration (including explicitly requested hidden scenes), batch exclusion of hidden scenes regardless of Show hidden scenes, filtered progress totals, and all-hidden generation. Its ResizeObserver stub allows Radix Scroll Area to mount in jsdom; scrollbar sizing and tile spacing require browser verification.
- `tests/media-seekers.test.tsx` covers section collapse/expansion, preference persistence across mounts, malformed/unavailable storage, continued polling while collapsed, elapsed/total time, drafts surviving polling, pointer/keyboard commits, shadcn/ui Slider millisecond pointer interaction and synchronization, custom one-second arrow-key movement preserving fractional positions and bounds, drag-time tooltip updates and dismissal, busy guards, unknown durations, inactive-source removal, serialized polling, unmount cleanup, error recovery, Preview/Program grouping and labels, empty groups, shared-source controls in both sections, accessible shared-source feedback, and Play/Pause/Stop state and actions. `tests/obs.test.ts` also covers Program and Preview media discovery, enabled nested scenes/groups, shared-source deduplication, exclusion of disabled items and unrelated OBS windows, millisecond seeking without scene changes, paused playback, rejection of inactive/unavailable media or invalid cursor positions, pending-seek invalidation after a Preview change, explicit playback actions, restart after stop/end, duration-independent Preview playback, guarded/failed commands, and pending playback invalidation after collection changes.
- `tests/output-badges.test.tsx` covers elapsed output time, inactive styling, recording pause, stream reconnection, independent unavailable status/recovery, serialized polling, hidden-tab suspension/resumption, and unmount cleanup. `tests/obs.test.ts` covers read-only output requests, reported durations, independent failures, rejection of replies from a disconnected session, explicit idempotent output start/stop, command failures, repeat-command guards, and no mutations after session replacement.
- `tests/navigation.test.tsx` also covers menu connection details, the output group without a visible Status heading, the Scenes submenu (keyboard open, generation/reset actions, busy guards, and visibility checkbox), starting each output, elapsed-time stop rows, cancelling/confirming each stop dialog, retry feedback, and session-change cleanup.
- `tests/navigation.test.tsx` covers the single-session navigation contract, Exit, connection-route redirects, and fullscreen availability on connections and during connection attempts with OBS-only entries hidden, fullscreen entry/exit, browser-exit synchronization, unsupported availability, busy-state independence, and rejected-request feedback using a mocked Fullscreen API.
- `tests/scene-previews.test.ts` covers enabled nested media traversal, 5-second/short-clip capture, playback/Preview restoration, Program protection, retries, external selection/session cancellation, unavailable-camera fallbacks (including failed status/cleanup requests), and seeking only the first usable source, and enabled capture-device detection through nested scenes/groups with disabled-device and audio exclusions. Protocol tests also cover natural capture without seeks, cached-image reuse, black rejection, and persisted-image hydration.
- `tests/preview-cache.test.ts` uses a controlled IndexedDB double to check targeted deletion with other collections retained, stale read/write rejection, fresh writes after reset, and storage failure/retry. Protocol tests cover current-scene reset keys (including hidden scenes), no OBS requests or scene changes, cleared in-memory thumbnails, obsolete hydration rejection, busy/repeat guards, retryable failures, and disconnect cleanup. These checks do not prove real browser IndexedDB transactions.
- `tests/screenshot-preview.test.ts` covers frame pacing, serialization, hidden tabs, backoff, and cancelled/stalled captures.
- `tests/screenshot-rendering.test.ts` covers decode-before-draw and obsolete frame rejection with controlled image/canvas doubles.
- `tests/obs-preview-hook.test.tsx` covers source/collection/mode lifecycle cleanup.
- `tests/scene-monitor.test.tsx` covers independent persisted mode settings, scene-name fallback, the Remote Preview dialog, cancellation, independent persistence, and credential opt-in, and local Program Fade duration, outgoing/incoming canvas continuity, reset cleanup, and disabled/Preview exclusions. Protocol tests cover Fade start snapshots, configured duration, renamed fades, and Cut exclusion.
- `tests/obs-qr.test.ts` covers OBS QR schemes, percent-encoded and absent passwords, IPv6, invalid ports/payloads, and credential-safe errors. `tests/qr-connections.test.tsx` covers scanned form values, explicit password persistence, camera failure/image upload, and cleanup/stale-result handling with a mocked decoder. These tests do not validate actual camera hardware or QR decoding.
- `tests/profiles.test.ts` covers password persistence, malformed storage, and URL validation.
- `tests/pwa-update.test.tsx` covers explicit update acceptance, postponement, connection/session guards, and update-error feedback. These mocks do not validate browser service-worker lifecycle behavior.

Browser acceptance must also verify toggling Active media by mouse and keyboard, visible focus and chevrons, hiding both groups, and retaining the choice after reload/reconnect. Confirm reopening shows current playback, the section disappears when all controllable media becomes inactive, and its preference survives that disappearance.

Media seek regressions also assert that releasing a slider preserves the selected position and elapsed time, pre-seek/in-flight polling cannot replace it, both copies of a shared source update optimistically, and a fresh read after command acknowledgment restores OBS authority. They cover unsuccessful seek rollback and older command completions leaving newer positions intact. Protocol tests assert the seek success/failure result used by that rollback. Near-end tests exercise exact 16/17/18-second requests for an 18-second simulated clip; a separate UI regression accepts a fresh keyframe-aligned cursor from OBS after an optimistic seek.

The protocol simulator is a controlled test double, not OBS. Passing tests do not establish real transition timing, scene-collection behavior, or browser network compatibility. Record browser/OBS observations separately. For documentation-only changes, verify claims against code and check Markdown links; application tests need rerunning only when executable inputs change.

## Live OBS acceptance checklist

Use an OBS instance and reachable WebSocket address supplied for testing. Record OBS version, browser/version, operating system, network/address scheme, and the date in the milestone acceptance notes when this is performed.

1. Verify reachable OBS endpoints (including password-protected ones) show Online, unavailable endpoints show Offline, and badges update after endpoint availability changes. Save and edit a connection. Reload to confirm persistence. Verify passwords are omitted unless Remember password is enabled, and removed after opting out.
   For QR import, open Add connection → Scan QR Code and scan OBS’s Connect Info QR using a camera or upload a screenshot. Verify the decoded address/password, percent-encoded special characters, authentication disabled, and explicit Remember password behavior. Test denied/missing camera access, unreadable/unrelated images, cancellation/close during permission and image requests, and camera release on success/close. Confirm a scan neither saves nor connects automatically.
2. Connect with valid credentials, then verify clear feedback for invalid credentials and an unavailable endpoint. Confirm cancellation leaves no usable stale controls. While connected, confirm the brand link and Browser Back keep the active studio visible; **Exit** must disconnect and return to saved connections. Verify “Connected to [device]” sits beside Exit on the left, with LIVE/REC badges on the right and the logo still centered. Below sm (640px), verify only the custom app icon remains, centered without wordmark spacing, with its StudioCTRL accessible link name retained. Connect while outputs are already active and compare HH:MM:SS against OBS. Start/stop streaming and recording externally, pause/resume recording, and check activity/timers update, inactive badges stay muted at zero, and paused recording is explicitly labeled without a locally advancing timer. Verify reconnecting-stream labels, unavailable read/recovery behavior, hidden-tab return, Exit/reconnect cleanup, long connection names, and the compact connection layout: hide its prefix below lg (1024px), truncate long names, and hide the whole connection badge below sm (640px). Check output badges using Radio/Video with timers hidden below md and visible paused/reconnecting details. Verify only LIVE/REC labels hide below lg (1024px), with timers visible at md and above and accessible full status retained. Open the actions menu at every width and verify its connection name, separators, output controls without a visible Status heading, inactive Start streaming/Start recording rows, and always-visible active-output timers. Start each output, open its stop confirmation by selecting the timer row, cancel/Escape without stopping, then confirm and verify OBS stops only that output. Check pending repeat guards, failure/retry feedback, focus moving into the dialog and returning to the actions trigger, keyboard navigation, externally stopped/paused/reconnecting outputs, unavailable-read disabling/recovery, and disconnect/profile replacement while a confirmation or command is pending. No output action may change Preview/Program or trigger a transition. These output/browser checks remain outstanding.

Re-enable OBS/Remote Preview and verify full 16:9 sizing returns, including loading/error states. At sm and above, No Preview must retain its full scene-name panel; from 640px through 900px, verify they remain side by side. From sm through 900px, verify the controls sit beneath both monitors with Show/Hide Previews left, Transition centered, and the combined settings button right. Below sm, verify the centered control group matches the monitors’ max-w-sm width: Transition spans the first row, with Show/Hide Previews and transition settings filling the second row side by side. ## PWA acceptance checklist

Use `bun run build` and `bun run preview` with the trusted local certificate, or a production HTTPS origin. `bun run dev` deliberately does not install a worker. The build should emit `manifest.webmanifest`, `sw.js`, a Workbox runtime, and the regular/maskable/Apple PNG icons. Regenerate committed icons after favicon changes with `bun run generate:icons` (uses the Sharp development dependency; generated PNGs are committed and normal builds do not regenerate them).

1. Inspect the manifest and service-worker registration in browser developer tools. Install from the browser menu; confirm the icon, standalone window, root startup, and route navigation. Record browser/version, OS, origin, and date.
2. Load once online and allow the worker to install. Close/reopen, then make the app server unavailable and open/reload `/` and `/studio`. Confirm the shell loads and starts disconnected, with no stale scenes or implied offline control. Verify a new connection fails honestly when OBS is also unreachable; app-server reachability and OBS reachability are separate.
3. Publish a second build with a visible change at the same origin, then reopen a window to trigger an update check. Confirm the release waits for **Reload to update**, **Later** keeps the current page, and connecting/connected states disable reload. Disconnect all windows, accept, and verify the new build loads. Repeat with multiple app windows and check activation after all windows close. Inspect cache cleanup after activation.
4. Verify the installed app can connect over the intended network and OBS address scheme, including browser permission prompts and WS/WSS restrictions. Interrupt OBS connectivity and confirm disconnected state and reconnect behavior. Cached assets must not hide an OBS connection failure.
5. Run `bun run deploy:check`. Use `bun run preview:worker` to confirm JavaScript for `sw.js`, the manifest media type for `manifest.webmanifest`, navigation fallback for `/studio` and `/studio/`, `no-cache` on entry files/routes, and immutable caching for fingerprinted `/assets/*`. Vite preview does not apply `_headers`. Repeat against the deployed origin. Exercise clients still loading the previous release during rollout; the current deploy scripts upload only the current `dist/` and do not retain previous fingerprinted files.

Automated tests cover the update UI, and the production build validates service-worker generation. They do not prove installation, offline startup, multi-window activation, or deployment/network compatibility; record that evidence in [milestones](milestones.md) only after exercising it.

## Remote Preview acceptance

Automated `tests/remote-preview.test.ts` uses controlled fetch/peer doubles for WHEP URL validation, UTF-8 Basic/bearer headers, credential opt-in/removal, server-advertised TURN, receive-only negotiation, DELETE cleanup, authentication errors, cancelled discovery, rejection of cross-origin session URLs, and separate audio/video track arrivals while playback is pending (source reassignment must not abort playback). DOM tests cover dialog open/cancel/save and per-monitor settings; these do not prove video decoding or browser networking.

With OBS publishing to your MediaMTX instance, record versions, codecs, browser/OS, controller/stream origin schemes, and network environment. Configure HTTPS/CORS/ICE as described in [README](../README.md#remote-preview-webrtc--mediamtx). For each monitor, choose Remote Preview and test a page URL and a full WHEP endpoint; check none/Basic/bearer authentication as configured, invalid credentials, read-permission denial, unpublished paths, and Retry after recovery. Verify actual moving video, muted audio, persistent overlays, letterboxing, and that Preview selection and transitions leave the remote subscription unchanged while the feed reflects the published output. Verify errors do not show credentials or server response bodies.

Test keyboard dialog navigation, focus return, Escape/Cancel preserving current playback, reopening/editing an already selected remote mode, and independent profile/monitor settings. Save with remembering off/on, reload, inspect storage, reenter unremembered credentials, then opt out and confirm old secrets are removed. Toggle both previews off/on and confirm each previous source returns. Disable remote playback, exit OBS, switch profiles, and edit/retry during slow signaling; verify old media, peer connections, and WHEP sessions are released and no stale video returns. Test unavailable servers, blocked CORS, bad certificates/mixed content, unreachable ICE addresses, codec mismatch, and network loss. Live validation remains outstanding until these checks are exercised against real MediaMTX and a browser.
